The HACS button opens HAPatchY as a **custom repository** in an existing HACS
installation. It does not indicate inclusion in HACS's default catalog.

HAPatchY is a Home Assistant custom integration that keeps a deliberate edit to
**one configuration file** when an update replaces it. You can edit an authorized
file in Home Assistant's native form and let HAPatchY generate a unified diff,
or supply a `.patch`/`.diff` yourself. When automatic application is enabled
and the file changes, HAPatchY checks the diff against its contents and applies
it only when the match is unambiguous.
A conflict stops the write and appears in the patch's status and Repairs.
HAPatchY does not bundle patches for other integrations.

## Start here

The [documentation site](https://ryther.github.io/hapatchy/) is organized by
task. For a first use:

1. [Install HAPatchY](https://ryther.github.io/hapatchy/installation/) through
   HACS or manually, then add the integration in Home Assistant.
2. [Authorize a directory](https://ryther.github.io/hapatchy/directory-permissions/)
   in both YAML settings and restart Home Assistant. No folder is permitted by
   default.
3. [Make your first patch](https://ryther.github.io/hapatchy/first-patch/) on an
   unused text file. The tutorial checks the applied bytes, backup and Revert.

You can also read the [guides directly on GitHub](https://github.com/Ryther/hapatchy/blob/main/docs/index.md).
Use the [settings and actions reference](https://ryther.github.io/hapatchy/reference/)
for exact behavior, or [troubleshooting](https://ryther.github.io/hapatchy/troubleshooting/)
when a check or action fails. The documentation tracks the current repository;
check the [release notes](https://github.com/Ryther/hapatchy/releases) if your
installed version differs.

## What to expect

The default **Add patch** flow lets you select a file on HA's server and edit its
contents in a plain multiline text field. Saving creates a managed diff and
requests immediate Apply with a backup. **A saved rule is not proof that Apply
succeeded**: check its status sensor, the target file and Home Assistant Repairs.
Other input modes let you paste or upload a diff or use an existing local patch
file or direct HTTPS URL. Each rule appears as a patch device with Status and
Patch health entities. There is no custom dashboard to install.

![A patch device with Status Applied and Patch health OK in disposable Home Assistant](https://raw.githubusercontent.com/Ryther/hapatchy/main/docs/images/patch-device.png)

This screenshot shows a checked example in disposable HA; read
[Your first patch](https://ryther.github.io/hapatchy/first-patch/) for the full
procedure and what to verify on disk.

HAPatchY can watch the target and reapply a compatible patch after an update.
It never forces an ambiguous match. A changed Python file may still need an HA
restart before the running integration uses the new code; HAPatchY never
restarts HA for you.

## Before using it

- A patch targets **one UTF-8 text file** under the HA configuration directory,
  not HA's installed core or arbitrary host paths. Matching requires exact,
  unique context; multi-file and fuzzy patches are not supported.
- Both HA's `allowlist_external_dirs` and HAPatchY's
  `hapatchy.allowed_directories` must permit the target. The file editor also
  lets an HA administrator API caller read file contents in those directories.
  Grant only folders whose future contents may be read and changed through that
  API. [Directory permissions](https://ryther.github.io/hapatchy/directory-permissions/)
  explains the boundary.
- The editor accepts nonempty UTF-8 LF text with a final newline, up to 512 KiB.
  It enables automatic Apply, startup checking and backup. Other input modes
  expose different behavior settings; see the
  [reference](https://ryther.github.io/hapatchy/reference/).
- Keep an independent backup. Removing a rule or uninstalling HAPatchY does
  **not** restore a changed file. Follow the checked
  [Revert and removal procedure](https://ryther.github.io/hapatchy/troubleshooting/#remove-a-patch-or-uninstall-hapatchy).

## Compatibility

| Tested Home Assistant baseline | Python in that test environment |
| --- | --- |
| **2026.7.4** — minimum supported HA | 3.14.7 |
| **2026.9.4** — development baseline | 3.14.7 |

The same integration code is tested at both endpoints. Intermediate HA releases
have not been individually tested. Your installed HA supplies Python: **HACS does
not download a separate Python interpreter or create a HAPatchY virtual environment**.
The development baseline is updated through a guarded PR when a newer stable HA
and its exact test plugin are available; a blocked candidate does not change the
tested version shown here.
HA 2026.7.4 requires Python 3.14.2 or newer. The minimum is a compatibility
baseline, not a recommendation to run an old, unpatched HA installation. Keep
HA updated within a version compatible with your other integrations.

## Compatibility contract

The documented single-file patch format, directory grants, native Add patch
flow, administrator actions, statuses and retained backups are the supported
user-facing interfaces. Incompatible changes to those interfaces require
a new major release. Exact matching can still fail after upstream changes;
conflicts and authorization failures stop writes. See the
[reference](https://ryther.github.io/hapatchy/reference/) for limits and recovery paths.

## Help and development

For help, start with [troubleshooting](https://ryther.github.io/hapatchy/troubleshooting/). When reporting a
problem in [GitHub Issues](https://github.com/Ryther/hapatchy/issues), include
versions, the status sensor's state and a sanitized example; review diagnostics
before sharing them.

AI assistants can use the self-contained
[HAPatchY user guide skill](https://github.com/Ryther/hapatchy/blob/main/.agents/skills/hapatchy-guide/SKILL.md) for
installation, patch actions and recovery. Codex and OpenCode find it in
`.agents/skills/`, and Claude Code through `.claude/skills/`. ChatGPT users with
Skills support can upload that skill folder. The skill gives guidance, not HA
access or approval for a patch destination.

Contributors should read [CONTRIBUTING.md](https://github.com/Ryther/hapatchy/blob/main/CONTRIBUTING.md), the
[architecture](https://ryther.github.io/hapatchy/architecture/),
[Dev Container guide](https://github.com/Ryther/hapatchy/blob/main/.devcontainer/README.md)
and [release process](https://ryther.github.io/hapatchy/releasing/).
The Dev Container starts a disposable
HA; it does not need your household installation.
